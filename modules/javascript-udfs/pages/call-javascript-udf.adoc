= Call a JavaScript User-Defined Function
:description: Call a JavaScript user-defined function from {sqlpp}, and run {sqlpp} statements from inside your JavaScript code.
:page-topic-type: guide
:page-toclevels: 2
:keywords: UDF, user-defined function, SQL++, JavaScript, variadic, N1QL()
:page-aliases: guides:call-user-defined-function.adoc, calling-javascript-from-n1ql.adoc, calling-n1ql-from-javascript.adoc

[abstract]
{description}

A JavaScript user-defined function (UDF) adds your own logic to {sqlpp}.
You write the logic as a JavaScript function.
Then you create a {sqlpp} user-defined function that points to the JavaScript function.

After you create the user-defined function, you can:

* Call the function from a {sqlpp} statement, the same way that you call a built-in function.
* Run {sqlpp} statements from inside the JavaScript function to read and change data in your operational cluster.
* Combine both, to build functions that query your data and return processed results to {sqlpp}.

For more information about the types of user-defined functions and how they work, see xref:guides:javascript-udfs.adoc[].

[#prerequisites]
== Prerequisites

* You have an operational cluster with the `travel-sample` sample dataset loaded.
For more information about how to create a cluster and load sample data, see xref:get-started:create-account.adoc[].
* You can run {sqlpp} statements from the Query tab or the cbq shell.
For more information about these tools, see xref:clusters:query-service/query-workbench.adoc[] and xref:n1ql:n1ql-intro/cbq.adoc[].
* You have a UDF library called `my-library` in the `inventory` scope of the `travel-sample` bucket.
For more information about how to create a library and add JavaScript functions to it, see xref:guides:create-javascript-library.adoc[].
* Your cluster access credentials have the privileges to execute user-defined functions.
They must also have the privileges to read or change any data that the function's {sqlpp} statements use.
For more information about privileges, see xref:clusters:cluster-rbac.adoc[].

[#call-from-sqlpp]
== Call a JavaScript Function from {sqlpp}

You can call a user-defined function inside any {sqlpp} expression, the same way that you call a built-in function.
You can also run a user-defined function on its own with the `EXECUTE FUNCTION` statement.

The name of a user-defined function is case-sensitive.
You must call the function with the same case that you used to create it.

[#keyspace-references]
=== Keyspace References Inside a Function

A {sqlpp} statement inside a JavaScript function can use a full keyspace path, such as `{backtick}travel-sample{backtick}.{backtick}inventory{backtick}.{backtick}airline{backtick}`.
It can also use a partial keyspace reference, such as `airline`.

{sqlpp} resolves partial keyspace references against the user-defined function, not the current query context:

* For a scoped function, {sqlpp} resolves partial keyspace references against the function's bucket and scope.
* For a global function, {sqlpp} resolves partial keyspace references against the `default:` namespace.

For example, `SelectAirlines` is a scoped function in `travel-sample`.`inventory`.
If its `SELECT` statement uses `FROM airline`, {sqlpp} reads from `travel-sample`.`inventory`.`airline` in any query context.

For more information about keyspace references, see xref:n1ql:n1ql-intro/queriesandresults.adoc#keyspace-reference[Keyspace References].

[#returned-results]
=== Use the Results of a {sqlpp} Statement

When a {sqlpp} statement returns values, such as a `SELECT` statement, it returns a JavaScript iterable.
Use a `for...of` loop to work with each document in the results.

In the `selectAirline` function, the variable `q` stores the iterable.
The function loops through `q`, copies the fields it needs into a new object, and adds each object to the `res` array.
Then it returns `res` to {sqlpp}.

How the JavaScript runtime runs a {sqlpp} statement depends on whether the statement returns a value:

* If the statement does not return a value, the runtime runs it synchronously.
The runtime waits for the statement to complete before it moves to the next line of JavaScript.

* If the statement returns a value, the runtime runs it asynchronously.
Your JavaScript continues to run before the iterable returns.
The Query Service fetches each document from the bucket when the iterable requests it.

[#transactions]
=== Use Transactions

{sqlpp} statements inside a JavaScript function support Couchbase transactions.

A JavaScript function can:

* Run statements in a transaction that started before the function started.
* Run a statement that starts a transaction.
* Run a statement that rolls back a transaction.

A {sqlpp} statement and its iterable must stay entirely inside the scope of a transaction.
If a transaction starts while your function loops through an iterable, you cannot fully roll back the transaction.

[#nested-calls]
=== Call Other Functions from a JavaScript Function

A JavaScript function can run a {sqlpp} statement that calls another user-defined function.
Use nested calls with care.

Each nested function call uses a new JavaScript worker.
Your operational cluster has 4 JavaScript workers for each CPU.
The deeper you nest your calls, the fewer workers stay available to run them.

Capella stops recursive calls when fewer than 50% of the total JavaScript workers are available.
The call chain then fails with an error.
