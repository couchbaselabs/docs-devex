[#function-statistics]
== Function Statistics on the Eventing Page

The Eventing page shows Deployment Statistics for each deployed Function.
To see them, click the Function's name on the *Eventing* page.

The statistics update every 10 seconds by default:

[cols="1,3"]
|====
| Statistic | Description

| success
| The number of Function invocations that succeeded, including timer callbacks.

| failure
| The number of Function invocations that failed while running the Function's code.

| timeout
| The number of Function invocations that exceeded the Function's script timeout.
|====

image::stats_00_counts.png["The Deployment Statistics for a deployed Function, showing the success, failure, and timeout counts",100%]

For more information about the script timeout, see xref:eventing-Terminologies.adoc#function-settings[Eventing Function Settings].

[#function-charts]
=== Rate Charts

Click *Charts* to show rate charts for the same 3 statistics:

* Successful Function Invocations Rate
* Failed Function Invocations Rate
* Eventing Timeouts Rate

The charts lag 30 seconds behind the current time.
To change the time range, use the list next to *Charts*.

image::stats_01_counts_and_charts.png["The Deployment Statistics with the 3 rate charts expanded",100%]

You can expand any chart to see it in more detail.

[#dashboard-statistics]
== Eventing Statistics on Custom Dashboards

Add Eventing charts to a custom dashboard to see Eventing statistics for a node or for the whole cluster.
Dashboard statistics combine all buckets and all Functions.
They do not show statistics for individual buckets or Functions.

The following Eventing statistics are available for dashboards:

[cols="1,1"]
|====
| Count | Rate

| Successful Function Invocations
| Successful Function Invocations Rate

| Failed Function Invocations
| Failed Function Invocations Rate

| Eventing Timeouts
| Eventing Timeouts Rate
|====

[#rest-api-statistics]
== Eventing Statistics with the REST API

Each Eventing node provides statistics through a REST API that listens on `localhost`, port 8096.
Each response contains statistics for that node only.
To get statistics for the whole cluster, collect the responses from every Eventing node and combine them.

To use these endpoints, you need the appropriate RBAC privileges.
Users with the Full Admin or Eventing Full Admin role can access any Eventing Function endpoint.
For more information, see xref:eventing-rbac.adoc[Eventing Role-Based Access Control].

To get the full set of Eventing statistics, run the following command on an Eventing node:

[source,sh]
----
curl -u $CB_USERNAME:$CB_PASSWORD "http://localhost:8096/api/v1/stats?type=full"
----

The response includes the following statistics:

* Event processing and events remaining
* Execution
* Failures
* Latency
* Worker process IDs
* Sequence numbers processed

If you omit `type=full`, the response excludes the following statistics:

* `dcp_event_backlog_per_vb`
* `doc_timer_debug_stats`
* `latency_stats`
* `plasma_stats`
* `seqs_processed`

To get individual statistics for a Function, use the following endpoints:

[source,sh]
----
curl -u $CB_USERNAME:$CB_PASSWORD "http://localhost:8096/getExecutionStats?name=$FUNCTION_NAME"
curl -u $CB_USERNAME:$CB_PASSWORD "http://localhost:8096/getLatencyStats?name=$FUNCTION_NAME"
curl -u $CB_USERNAME:$CB_PASSWORD "http://localhost:8096/getFailureStats?name=$FUNCTION_NAME"
----
