= REVOKE
:description: Use the REVOKE statement to remove Role-Based Access Control (RBAC) roles or credential access from a user or group.
:page-topic-type: reference
:imagesdir: ../../assets/images

:authorization-overview: xref:learn:security/authorization-overview.adoc
:logical-hierarchy: xref:n1ql-intro/queriesandresults.adoc#logical-hierarchy
:keyspace-ref: xref:n1ql-language-reference/createindex.adoc#keyspace-ref

[abstract]
{description}

You can use `REVOKE` to remove two types of access:

Roles:: Revokes RBAC roles from a user or group, removing a predefined set of privileges.
Roles can be simple or parameterized by a keyspace.
For more information, see <<role-types>>.

Credentials:: Revokes a user or group's permission to use a specific credential from the credential store.
+
To revoke access to a credential, use the `REVOKE CONSUME CREDENTIALSTORE` statement.
This statement revokes the Credential Consumer RBAC role from the user or group.
For example, you can revoke a user's access to a specific AWS credential.

//TODO: For more information about credentials and the credential store, see xref:<link>. Link to the credential store doc.

[NOTE]
====
* Only Full Administrators can run the `REVOKE` statement.
For more information about user roles, see {authorization-overview}[Authorization].
* The `REVOKE CONSUME CREDENTIALSTORE` statement is available only in Couchbase Server 8.5 and later.
====

== Role Types

Roles can be of the following two types:

simple::
Roles which apply generically to all keyspaces/resources in the cluster.
+
For example: `cluster_admin` or `bucket_admin`

parameterized by a keyspace::
Roles which are defined for the context of the specified keyspace only.
Specify the keyspace name after the keyword ON.
+
For example: `pass:c[data_reader ON `travel-sample`]` +
or `pass:c[query_select ON `travel-sample`.`inventory`.`airline`]`

== Usage

The REVOKE statements have three forms:

.{counter:form}. Unparameterized Roles
[source,sqlpp]
----
REVOKE replication_admin, query_external_access
   FROM cchaplan, jgleason;
----

.{counter:form}. Parameterized Roles
[source,sqlpp]
----
REVOKE query_select, views_admin
   ON orders, customers
   FROM bill, linda;
----

.{counter:form}. Credentials Access
[source, sqlpp]
----
REVOKE CONSUME CREDENTIALSTORE ON `aws_key`
   FROM linda;
----

[NOTE]
====
* You cannot mix parameterized and unparameterized roles or syntax in the same statement, and doing so results in an error.
* `REVOKE CONSUME CREDENTIALSTORE` revokes access to a named credential in the credential store rather than an RBAC role, and you cannot mix it with role-based `REVOKE` syntax in the same statement.
====

== Examples

.Revoke the Cluster Admin role from multiple users
====
[source,sqlpp]
----
REVOKE cluster_admin FROM david, michael, robin
----
====

.Revoke Query Select and Data Reader roles on the `travel-sample` keyspace from a specific user
====
[source,sqlpp]
----
REVOKE query_select, data_reader
  ON `travel-sample`
  FROM debby
----
====

.Revoke the Data Reader role on the `travel-sample` keyspace from a specific group
====
[source,sqlpp]
----
REVOKE query_update
  ON `travel-sample`
  FROM GROUP sales
----
====

.Revoke a specific user's permission to consume an AWS credential
====
The following statement revokes a user's permission to consume the credential `awsid`.

[source,sqlpp]
----
REVOKE CONSUME CREDENTIALSTORE ON `awsid` FROM debby;
----
====

.Revoke a group's permission to consume multiple credentials
====
The following statement revokes a group's permission to consume the credentials `awsid` and `backup_s3`.

[source,sqlpp]
----
REVOKE CONSUME CREDENTIALSTORE ON `awsid`, `backup_s3` FROM GROUP sales;
----
====
