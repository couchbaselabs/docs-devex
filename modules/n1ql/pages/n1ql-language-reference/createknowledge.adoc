[abstract]
{description}

Knowledge is made up of entries.
Each entry has a name and a value.
The name is a string used to identify the entry.
The value is a free-form, natural language string, giving a domain or ontology hint: for example, `"ICAO codes represent airports"`.

Knowledge is stored in a collection within a scope.
Each collection may contain zero, one, or multiple knowledge entries.

You can use knowledge to add contextual information to an LLM request, such as USING AI or BEGIN CHAT.
The knowledge is concatenated into the prompt sent to the LLM.

== Prerequisites

The keyspace must exist before you create knowledge in it.

.RBAC Privileges
To execute the CREATE KNOWLEDGE statement, you must have the Full Admin role.
For more information, see {authorization-overview}[Authorization].

[[or-replace]]
=== OR REPLACE Clause

The optional `OR REPLACE` clause enables you to redefine knowledge entries if they already exist.

When a knowledge entry with the same name already exists within the same context:

* If the `OR REPLACE` clause is present, the existing knowledge entry is replaced.

* If the `OR REPLACE` clause is not present, an error is generated.

namespace::
(Optional) An {identifiers}[identifier] that refers to the {logical-hierarchy}[namespace] of the keyspace.

If the namespace name is omitted, the default namespace in the current session is used.

(Required) An {identifiers}[identifier] that refers to the {logical-hierarchy}[bucket name] of the keyspace.

(Optional) An {identifiers}[identifier] that refers to the {logical-hierarchy}[scope name] of the keyspace.

(Optional) An {identifiers}[identifier] that refers to the {logical-hierarchy}[collection name] of the keyspace.

== Usage

Within a conversational chat (started with BEGIN CHAT, continued via its `chatId` or `natural_chatid`), knowledge injection only happens on the chat's first request, when its prompt is first built.
On every subsequent turn that continues the same chat, the cached prompt is reused directly and knowledge is not gathered or injected again -- even if `AND KNOWLEDGE` / `WITH {"knowledge": true}` is specified again on that later turn.
To have knowledge entries included, they should exist and be requested on the first message of the chat.

== Examples

.Create knowledge with full path
====
This statement creates a knowledge entry called `icao_hint` in the `{backtick}travel-sample{backtick}.inventory.airport` keyspace.

[source,sqlpp]
----
CREATE KNOWLEDGE icao_hint FOR `travel-sample`.inventory.airport
AS "ICAO codes represent airports.";
----
====

.Create knowledge with query context
====
include::ROOT:partial$query-context.adoc[tag=example]

This statement creates a knowledge entry called `iata_hint` in the `{backtick}travel-sample{backtick}.inventory.airport` keyspace.

[source,sqlpp]
----
CREATE KNOWLEDGE iata_hint FOR airports
AS "IATA codes represent airports, and cities or metropolitan areas with multiple airports.";
----
====

.Create and replace knowledge
====
include::ROOT:partial$query-context.adoc[tag=example]

This statement creates a knowledge entry called `icao_hint` in the `{backtick}travel-sample{backtick}.inventory.airport` keyspace.

If the knowledge entry already exists, it's replaced.

[source,sqlpp]
----
CREATE OR REPLACE KNOWLEDGE icao_hint FOR airport
AS "ICAO codes are 4-letter airport codes used internationally.";
----
====

.Create multiple knowledge entries
====
include::ROOT:partial$query-context.adoc[tag=example]

This statement creates multiple knowledge entries in the `{backtick}travel-sample{backtick}.inventory.airport` keyspace.

[source,sqlpp]
----
CREATE OR REPLACE KNOWLEDGE FOR airport
FROM { "icao_hint": "ICAO codes are 4-letter airport codes used internationally",
       "iata_hint": "IATA codes are 3-letter codes representing airports, and cities or metropolitan areas with multiple airports, around the world."};
----
====
