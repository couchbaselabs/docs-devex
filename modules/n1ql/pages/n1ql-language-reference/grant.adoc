[#grant-roles]
=== Roles
:section: roles

This syntax grants RBAC roles to a user or group, giving them a predefined set of privileges.
Roles can be simple or parameterized by a keyspace.

* Simple roles, such as `cluster_admin` or `bucket_admin`, apply generically to all keyspaces or resources in the cluster.
* Parameterized roles, such as `data_reader` or `query_select`, are defined for the context of the specified keyspaces only.
Use the ON clause to specified the keyspaces.

You cannot mix simple and parameterized roles in the same statement, and doing so results in an error.

==== TO Clause

The TO clause enables you to specify the users or groups that the statement applies to.

[source,ebnf]
----
include::partial$grammar/dcl.ebnf[tag=users-or-groups]
----

image::n1ql-language-reference/users-or-groups.png["Syntax diagram: see source code listing", align=left]

[horizontal]
user::
A user name created by the {product-name} RBAC system.
When specifying users, the keyword `USER` or `USERS` is optional.

group::
A group name created by the {product-name} RBAC system.
When specifying groups, you must include the keyword `GROUP` or `GROUPS`.

You can use either the singular or plural form of these keywords.
This does not affect the number of users or groups the statement applies to.

Currently, only one credentialstore privilege is available: `CONSUME CREDENTIALSTORE`.

For example, you can grant a user access to a specific AWS credential.

== Examples

.Grant an unparameterized role
====
The following example grants the role of Cluster Admin to multiple users.

[source,sqlpp]
----
GRANT cluster_admin TO david, michael, robin;
----
====

.Grant parameterized roles
====
The following example grants Query Select and Data Reader roles on the `travel-sample` keyspace to a specific user.

[source,sqlpp]
----
GRANT query_select, data_reader ON `travel-sample` TO debby;
----
====

.Grant a parameterized role to a group
====
The following example grants the role of Data Reader on the `travel-sample` keyspace to a specific group.

[source,sqlpp]
----
GRANT data_reader ON `travel-sample` TO GROUP sales;
----
====

.Grant a user permission to consume a credential
====
The following statement grants a user permission to consume the credential `awsid`.
To create this credential, see the examples in xref:n1ql:n1ql-language-reference/createcredentialstore.adoc#examples[CREATE CREDENTIALSTORE].

[source,sqlpp]
----
GRANT CONSUME CREDENTIALSTORE ON `awsid` TO debby;
----
====

.Grant a group permission to consume multiple credentials
====
The following statement grants a group permission to consume the credentials `awsid` and `backup_s3`.
To create these credentials, see the examples in xref:n1ql:n1ql-language-reference/createcredentialstore.adoc#examples[CREATE CREDENTIALSTORE].

[source,sqlpp]
----
GRANT CONSUME CREDENTIALSTORE ON `awsid`, `backup_s3` TO GROUP sales;
----
====

.Grant permission to query using an external catalog
====
The following example grants the user `analyst`:

* The Query External Catalog Select role on `sales_catalog`.
* The Credential Consumer role for the `query/external/iceberg-sales-catalog`.
and `query/external/iceberg-sales-table` credentials.
* The Query Select role on the `orders` collection.

[source,sqlpp]
----
GRANT SELECT CATALOG ON sales_catalog TO analyst;

GRANT CONSUME CREDENTIALSTORE
  ON `query/external/iceberg-sales-catalog`,
     `query/external/iceberg-sales-table`
  TO analyst;

GRANT query_select ON `sales`.`_default`.`orders` TO analyst;
----
====
