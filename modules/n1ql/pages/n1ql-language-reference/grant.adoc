= GRANT
:description: Use the GRANT statement to assign Role-Based Access Control (RBAC) roles or credential access to a user or group.
:page-topic-type: reference
:imagesdir: ../../assets/images

:authorization-overview: xref:learn:security/authorization-overview.adoc
:logical-hierarchy: xref:n1ql-intro/queriesandresults.adoc#logical-hierarchy
:keyspace-ref: xref:n1ql-language-reference/createindex.adoc#keyspace-ref

[abstract]
{description}

You can use `GRANT` to provide two types of access:

Roles:: Grants RBAC roles to a user or group, giving them a predefined set of privileges.
Roles can be simple or parameterized by a keyspace.
For more information, see <<role-types>>.

Credentials:: Grants a user or group permission to use a specific credential from the credential store.
+
To grant access to a credential, use the `GRANT CONSUME CREDENTIALSTORE` statement.
This statement grants the Credential Consumer RBAC role to the user or group. 
For example, you can grant a user access to a specific AWS credential.

//TODO: For more information about credentials and the credential store, see xref:<link>. Link to the credential store doc.

[NOTE]
====
* Only Full Administrators can run the `GRANT` statement.
For more information about user roles, see {authorization-overview}[Authorization].
* The `GRANT CONSUME CREDENTIALSTORE` statement is available only in Couchbase Server 8.5 and later.
====

== Role Types

Roles can be of the following two types:

simple::
Roles that apply generically to all keyspaces or resources in the cluster.
+
For example: `cluster_admin` or `bucket_admin`

parameterized by a keyspace::
Roles that are defined for the context of the specified keyspace only.
Specify the keyspace name after the keyword `ON`.
+
For example: `pass:c[data_reader ON `travel-sample`]` +
or `pass:c[query_select ON `travel-sample`.`inventory`.`airline`]`

== Usage

The GRANT statements have three forms: 

.{counter:form}. Unparameterized Roles
[source,sqlpp]
----
GRANT replication_admin, query_external_access
   TO cchaplan, jgleason;
----

.{counter:form}. Parameterized Roles
[source,sqlpp]
----
GRANT query_select, views_admin
   ON orders, customers
   TO bill, linda;
----

.{counter:form}. Credentials Access
[source, sqlpp]
----
GRANT CONSUME CREDENTIALSTORE ON `aws_key`
   TO linda;
----

[NOTE]
====
* You cannot mix parameterized and unparameterized roles or syntax in the same statement, and doing so results in an error. 
* `GRANT CONSUME CREDENTIALSTORE` grants access to a named credential in the credential store rather than an RBAC role, and you cannot mix it with role-based `GRANT` syntax in the same statement.
====

== Examples

.Grant the role of Cluster Admin to multiple users
====
[source,sqlpp]
----
GRANT cluster_admin TO david, michael, robin;
----
====

.Grant Query Select and Data Reader roles on the `travel-sample` keyspace to a specific user
====
[source,sqlpp]
----
GRANT query_select, data_reader ON `travel-sample` TO debby;
----
====

.Grant the role of Data Reader on the `travel-sample` keyspace to a specific group
====
[source,sqlpp]
----
GRANT data_reader ON `travel-sample` TO GROUP sales;
----
====

.Grant a specific user permission to consume an AWS credential
====

The following statement grants a user permission to consume the credential `awsid`.
To create this credential, see the examples in xref:n1ql:n1ql-language-reference/createcredentialstore.adoc#examples[CREATE CREDENTIALSTORE].

[source,sqlpp]
----
GRANT CONSUME CREDENTIALSTORE ON `awsid` TO debby;
----
====

.Grant a group permission to consume multiple credentials
====

The following statement grants a group permission to consume the credentials `awsid` and `backup_s3`.
To create these credentials, see the examples in xref:n1ql:n1ql-language-reference/createcredentialstore.adoc#examples[CREATE CREDENTIALSTORE].

[source,sqlpp]
----
GRANT CONSUME CREDENTIALSTORE ON `awsid`, `backup_s3` TO GROUP sales;
----
====
