= USING AI
:description: The USING AI statement allows you to generate SQL++ queries from natural language prompts.
:page-topic-type: reference

[abstract]
{description}

== Purpose

You can use the USING AI statement to input natural language queries through {sqlpp} interfaces such as CBQ shell, REST APIs, and SDKs. 
When executed, the statement passes the input to Large Language Models (LLMs) which interpret the request and return the equivalent {sqlpp} query. 

For example, you can input prompts such as `How many airlines are based in Europe` or `List the names of all hotels in the same city as an airport`, and the statement will generate the corresponding SQL++ queries. 

If the generated {sqlpp} query is a SELECT statement, the system automatically executes it and returns the results.
For others, the generated query is returned as a string without execution.

=== Options

[cols="1a,3a,1a"]
|===
| Name | Description | Schema

| **creds** +
__optional__
| Credentials to use for the request. 
This can be a string matching the `natural_cred` specification or an object with the fields `user` and `pass`, similar to the xref:n1ql:n1ql-manage/query-settings.adoc#Credentials[`creds`] parameter.

If specified, it overrides the default `natural_cred` parameter.

| String or object

| **keyspaces** +
__optional__

| Keyspaces to use for the request.
This can be a string matching the `natural_context` specification or an array of comma-separated strings, which when joined, provide the value. 

If specified, it overrides the default `natural_context` parameter.

| String or an array of strings 

| **orgId** +
__optional__

| Organization ID to use for the request.

If specified, it overrides the default `natural_orgid` parameter.

| String

| **execute** +
__optional__

| Indicates if the generated statement should be executed immediately. 
It provides the ability to suppress the execution of the generated statement.

If set to `TRUE`, the generated statement is executed immediately and the results are returned.
If set to `FALSE`, the generated statement is returned as a string without execution.

*Default:* `TRUE`

| Boolean
|===

=== Handling Passwords Securely

Use `creds` and `natural_cred` parameters with caution to avoid exposing password information through history files or logs.
When working with the cbq shell, avoid passing passwords directly on the command line. 
Instead, use the `\set` command to specify only the username, and then enter the password at the terminal prompt.
This ensures that the password is not recorded in the shell history.

Similarly, if you are sending requests directly to a REST endpoint from a shell, be mindful of how you provide the password and whether it will be recorded in the shell history.
Consider using a method like the following to prompt for the password:

[source,sh]
----
echo -n "Enter your password: "
read -s p
echo
curl -s -d "natural_cred=<<your-username>>:${p}" \
     -d "natural_orgid=<<your-org-ID>>" \
     <url>
----

If you choose to reuse the password by setting an evironment variable, note that it might be visible to other users on the system with sufficient privileges for process inspection (for example, through `/proc`).
If security is a concern, consider using an HTTPS connection. 

== Examples

.Natural language prompt with the default parameters
====
.Request
[source, console]
----
cbq> \set -natural_context travel-sample.inventory.hotel;
cbq> \set -natural_cred "username@couchbase.com";
Enter password for "natural_cred":
cbq> \set -natural_orgId 7a99d00c-####-4b39-bc72-############;
cbq> USING AI How many hotels provide free parking?;
----
.Response

----
