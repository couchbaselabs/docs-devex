= Token Functions
:description: Tokenization is the process of breaking a stream of text up into words, phrases, symbols, or other meaningful elements called tokens.
:page-topic-type: reference
:example-caption!:

{description}
The list of tokens becomes input for further processing such as parsing or text mining.
Token functions are not limited to string input since they work with generic JSON objects and documents.

NOTE: If any arguments to any of the following functions are `MISSING` then the result is also `MISSING` (i.e.
no result is returned).
Similarly, if any of the arguments passed to the functions are `NULL` or are of the wrong type (e.g.
an integer instead of a string), then `NULL` is returned as the result.

[#section_kqy_hj4_qz]
== CONTAINS_TOKEN

Checks whether a token in the input object exactly matches the specified search token.

This function has an alias `HAS_TOKEN`.

=== Syntax

....
CONTAINS_TOKEN(input_obj, token_expr [, options ])
....

==== Arguments
input_obj:: Any JSON object, or any valid xref:n1ql-language-reference/index.adoc[expression] which evaluates to a string, to search within.

token_expr:: A token string, or any valid xref:n1ql-language-reference/index.adoc[expression] which evaluates to a string, that is being searched for.

options::
An optional JSON object to control tokenization. 
For more information, see <<options>>.

==== Options 

[cols="1,3,1"]
|===
|Name |Description |Schema

|`names`
a| Determines whether search within JSON object key names. 

* If `true`, includes key names in tokenization.
* If `false`, ignores key names and searches values only.

*Default:* `true`
|Boolean

|`case`
| Converts characters for case folding. 
Supported values are `"lower"` and `"upper"`. 

By default, the function preserves the original casing. 

|String

|`specials`
a| Determines whether to treat strings with special characters (such as email addresses and URLs) as single tokens.

* If `true`, keeps strings with special characters as single tokens (for example, `user@example.com`).
* If `false`, splits strings on special characters (for example, `user`, `example`, `com`).

*Default:* `false`

|Boolean

|`split`
a| Determines whether to split string values into individual word tokens.

* If `true`, splits strings into words based on whitespace.
* If `false`, treats the entire string value as a single token. 

*Default:* `true`

|Boolean

|`trim`
a| Determines whether to remove leading and trailing whitespaces around unsplit string values. 

* If `true`, trims whitespaces around unsplit strings.
* If `false`, retains original whitespace around unsplit strings. 

*Default:* `true`
|Boolean
|===

=== Return Value
A boolean, representing whether the search expression exists within the input object.

The function returns `true` if the sub-string exists within the input string, else returns `false`.

=== Example

.Finding hotels with the word "Inn" within their name
====
[source,sqlpp]
----
SELECT name
FROM [
  {"name": "Sportsman Inn"},
  {"name": "Keefer's Inn"},
  {"name": "Quality Inn King City Hotel"},
  {"name": "Premier Inn, Albert Dock"},
  {"name": "Central Bakery"}
] AS hotel
WHERE CONTAINS_TOKEN(name, "Inn", {"specials":true});
----

[source,json]
----
[
  {
    "name": "Sportsman Inn"
  },
  {
    "name": "Keefer's Inn"
  },
  {
    "name": "Quality Inn King City Hotel"
  },
  {
    "name": "Premier Inn, Albert Dock"
  }
]
----
====

=== Example

.Finding email addresses of UK hotels
====
[source,sqlpp]
----
SELECT email
FROM [
  {"email": "glencoe@syha.org.uk"},
  {"email": "owner@hillhousellanrhidian.co.uk"},
  {"email": "julia@number38thegower.co.uk"},
  {"email": "stay@holiday-harlech.co.uk"},
  {"email": "info@parishotel.fr"}
] AS hotel
WHERE CONTAINS_TOKEN_LIKE(email, "%uk", {"specials":true});
----

]
----
