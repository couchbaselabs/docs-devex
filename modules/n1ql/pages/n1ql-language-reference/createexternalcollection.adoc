[abstract]
{description}

An external collection enables you to query an Apache Iceberg table.
The collection itself does not store any data.
It uses a Couchbase catalog to point to the Iceberg table's metadata and storage location.

External collections are read-only.
You can only perform queries on them using the {select}[SELECT] statement.

// tag::validation[]
{product-name} does not validate any of the options for an external collection until you attempt to query the collection. 
// end::validation[]

== Prerequisites

You must create the catalog before you can create the external collection.
For more information, see xref:createcatalog.adoc[].

You must create a credential in the credential store that {product-name} uses to communicate with the storage backend.
For more information, see xref:learn:security/credential-store.adoc[].

include::createcollection.adoc[tag=usage]

.RBAC Privileges
To execute the CREATE EXTERNAL COLLECTION statement, clients must have the Bucket Admin or Manage Scopes role on the bucket, or any Administrative role that gives permission to add, edit, and drop scopes and collections in the bucket.
For more information, see {authorization-overview}[Authorization].

[[on]]
=== ON Clause

Use the `ON` clause to specify the name of the catalog on which the external collection is based.

[horizontal]
catalog::
The name of an existing catalog.

[[at]]
=== AT Clause

Use the `AT` clause to specify the ID of the credential that Couchbase Server uses to authenticate with the storage backend.

[horizontal]
credential::
The name of an existing credential in the credential store.

[[with]]
=== WITH Clause

Use the `WITH` clause to specify additional options for the collection.

[horizontal]
options::
An object representing the options to be set for the collection.

== Usage

You must grant clients the following roles to use a catalog and external collection:

* The Query External Catalog Select role on the catalog.
* The Credential Consumer role for the credentials used by the catalog and the external collection.
* The Query Select role on the external collection.

For more information, see xref:grant.adoc[].

== Examples

[#ex-create-external-collection]
.Create an external collection
====
This statement creates an external collection that exposes the `orders` table from `sales_catalog`.

[source,sqlpp]
----
CREATE EXTERNAL COLLECTION sales._default.orders
ON sales_catalog
AT `query/external/iceberg-sales-table`
WITH {
  "namespace": "sales_db",
  "tableName": "orders"
};
----
====

[#ex-create-external-collection-context]
.Create an external collection with query context
====
For this example, set the query context to the `external` scope in the travel sample dataset.
For more information, see xref:n1ql:n1ql-intro/queriesandresults.adoc#query-context[Query Context].


Assuming that the query context is set, this example creates an external collection called `flights` in the `external` scope within the `travel-sample` bucket.

The external collection exposes the `flights` table from `flights_catalog`.

[source,sqlpp]
----
CREATE EXTERNAL COLLECTION flights
ON flights_catalog
AT `query/external/iceberg-flights-table`
WITH {
  "namespace": "flight_data",
  "tableName": "flights"
};
----
====

[#ex-create-external-collection-not-exist]
.Create an external collection if it does not exist
====
For this example, set the query context to the `external` scope in the travel sample dataset.
For more information, see xref:n1ql:n1ql-intro/queriesandresults.adoc#query-context[Query Context].

Assuming that the query context is set, this statement creates a collection called `flights` in the `external` scope within the `travel-sample` bucket.

Unlike <<Create external collection with query context>>, if the `flights` collection already exists, the statement does nothing and no error is generated.

[source,sqlpp]
----
CREATE EXTERNAL COLLECTION IF NOT EXISTS flights
ON flights_catalog
AT `query/external/iceberg-flights-table`
WITH {
  "namespace": "flight_data",
  "tableName": "flights"
};
----
====
