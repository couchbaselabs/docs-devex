[abstract]
{description}

An external catalog uses a catalog provider to let you query data stored in Apache Iceberg tables in a cloud object store.

Catalogs are global: they're not restricted to any particular scope or collection in the Couchbase {logical-hierarchy}[logical hierarchy].
The CREATE CATALOG statement is not affected by the current query context.

// tag::validation[]
Couchbase {product-name} does not validate any of the options for a catalog until you attempt to query an external collection which uses the catalog.
// end::validation[]

== Prerequisites

You must create a credential in the credential store that Couchbase {product-name} uses to communicate with the catalog provider.
For more information, see xref:learn:security/credential-store.adoc[].

.RBAC Privileges
To execute the CREATE CATALOG statement, clients must have the External Catalog Admin role, or any Administrative role that gives permission to create, read, update, and delete external catalogs.
For more information, see {authorization-overview}[Authorization].

[[if-not-exists]]
=== IF NOT EXISTS Clause

The optional `IF NOT EXISTS` clause enables the statement to complete successfully when the specified catalog already exists.
If a catalog with the same name already exists, then:

* If this clause is not present, an error is generated.

* If this clause is present, the statement does nothing and completes without error.

[[type]]
=== TYPE Clause

Use the `TYPE` clause to specify the type of catalog.
The only supported catalog type is `ICEBERG`.

[[source]]
=== SOURCE Clause

Use the `SOURCE` clause to specify the catalog provider for this catalog.
The following catalog providers are supported.

The `REST` and `UNITY_CATALOG` catalog providers are synonyms.

[[at]]
=== AT Clause

Use the `AT` clause to specify the ID of the credential that Couchbase {product-name} uses to authenticate with the catalog provider.
This clause is required.
If you do not need to specify a credential, specify an empty string `""`.

[horizontal]
credential::
The name of an existing credential in the credential store.

[[with]]
=== WITH Clause

:credentialId: Accepted, but has no effect.
:required: required

Use the `WITH` clause to specify connection options for the catalog.
This clause is required.
If you do not need to specify any options, specify an empty object `{}`.

[horizontal]
options::
An object representing the options to be set for the catalog.
The options that are available depend on the catalog provider.

== Usage

External catalogs are listed in the `system:catalog` namespace.
For more information, see xref:n1ql-intro/sysinfo.adoc#querying-catalogs[Query Catalogs].

You must create an external collection to be able to query the data made available by the catalog.
For more information, see xref:n1ql-language-reference/createexternalcollection.adoc[].

You must grant clients the following roles to use a catalog and external collection:

* The Query External Catalog Select role on the catalog.
* The Credential Consumer role for the credentials used by the catalog and the external collection.
* The Query Select role on the external collection.

For more information, see xref:n1ql-language-reference/grant.adoc[].

== Examples

.Create a catalog
====
The following example creates a catalog for a REST catalog provider.

[source,sqlpp]
----
CREATE CATALOG sales_catalog
TYPE ICEBERG SOURCE REST
AT `query/external/iceberg-sales-catalog`
WITH { "uri": "https://iceberg-catalog.example.com" };
----
====

.Create a catalog if it does not exist
====
The following example creates a catalog for an AWS Glue catalog provider.

If `flight_catalog` already exists, the statement does nothing and no error is generated.

[source,sqlpp]
----
CREATE CATALOG IF NOT EXISTS flights_catalog
TYPE ICEBERG SOURCE AWS_GLUE
AT `query/external/iceberg-flights-catalog`
WITH {};
----
====
