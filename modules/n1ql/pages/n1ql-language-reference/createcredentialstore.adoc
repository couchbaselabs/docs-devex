== Purpose

The CREATE CREDENTIALSTORE statement creates a named credential in the credential store.

The credential store securely holds credentials that Couchbase services and users use to authenticate with external systems. Examples of external systems include AWS S3, REST APIs, and another Couchbase Server or Capella cluster.
For more information about the credential store, see xref:<link>. 

// TODO: Link to the credential store documentation. 

After you create a credential, you can reference it by name from other statements and features that authenticate with that external system, rather than specifying the raw credential values. 

A credential can also include an optional description, an expiration date, and guardrails that restrict its use. 

TIP: To let other users or groups use a credential that you created, grant them access with the GRANT CONSUME CREDENTIALSTORE statement. 
For more information, see xref:n1ql:n1ql-language-reference/grant.adoc[].

== Syntax

[source,ebnf]
----
include::partial$grammar/ddl.ebnf[tag=create-credentialstore]
----

[horizontal]
name::
(Required) An {identifier}[identifier] that represents the name of the credential to create.
The name must be unique within the credential store.

with-fields::
(Required) A JSON object that contains the credential type, the fields associated with that type, and optional settings. 
See <<with>>.

[[with]]
=== WITH Clause

Use the `WITH` clause to specify the additional credential fields. 

[horizontal]
type::
(Required) The type of external system the credential authenticates with.
This value determines which other fields `with-fields` must contain.
+
Supported values include: 
+
--
* `couchbase`
* `aws`
* `azureShared`
* `azureAd`
* `azureSas`
* `azureManaged`
* `gcp`
* `http`
--
+
Several of these values cover more than one credential variant, and the variant is determined by which fields you supply.
See <<credential-types>>.

description::
(Optional) A description of the credential.

expiresAt::
(Optional) An expiration timestamp, in epoch milliseconds, set to at least 5 minutes in the future.
After this time passes, all attempts to use the credential fail with an error.

guardrails::
(Optional) A JSON object that restricts how and where the credential can be used, such as which services can use it or which URLs it's valid for.
+

The candidate fields (allowedServices, urlWhitelist, allowedResources, allowedOperations) come from the REST API design, and that design itself has open questions about whether allowedResources and allowedOperations are implemented.

[[credential-types]]
.Fields by credential type
[cols="2,1,3,3", options="header"]
|===
| Credential type | `type` value | Required fields | Optional fields

| Couchbase Server or Capella (Basic + TLS)
| `couchbase`
| `username`, `password`, `encryptionType`
| `rootCertificate`

| Couchbase Server or Capella (mutual TLS)
| `couchbase`
| `clientCertificate`, `clientKey`, `encryptionType=full`
| `passphrase`, `rootCertificate`

| AWS S3
| `aws`
| `accessKeyId`, `secretAccessKey`, `region`
| `sessionToken`, `endpoint`

| Azure Storage (shared key)
| `azureShared`
| `accountName`, `accountKey`
| `endpoint`

| Azure (client secret)
| `azureAd`
| `clientId`, `clientSecret`, `tenantId`
| `endpoint`

| Azure (client certificate)
| `azureAd`
| `clientId`, `clientCertificate`, `tenantId`
| `clientCertPassword`, `endpoint`

| Azure (SAS token)
| `azureSas`
| `accountName`, `sharedAccessSignature`
| `endpoint`

| Azure (managed identity)
| `azureManaged`
| `managedIdentityId`
| `endpoint`

| GCP (service account)
| `gcp`
| `jsonCredentials`
| `region`, `endpoint`

| GCP (backup service)
| `gcp`
| `accessKeyId`, `secretAccessKey`
| `region`, `endpoint`

| HTTP Basic authentication
| `http`
| `authScheme` (`basic`), `username`, `password`
|

| HTTP Bearer token
| `http`
| `authScheme` (`bearer`), `token`, `headerName`
|

| HTTP mutual TLS
| `http`
| `authScheme` (`mtls`), `certificate`, `privateKey`
| `passphrase`, `rootCertificate`
|===

NOTE: Couchbase never returns fields that contain secret values (such as `secretAccessKey`, `accountKey`, or `clientSecret`) in plain text after you set them. 

== Examples

.Create a credential named `awsid` for an AWS access key
====
[source,sqlpp]
----
CREATE CREDENTIALSTORE `awsid` WITH {
    "type": "aws_key",
    "accessKeyId": "AKIAIOSFODNN7EXAMPLE",
    "secretAccessKey": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
    "region": "us-west-2"
};
----
====
