== Purpose

The `CREATE CREDENTIALSTORE` statement creates a named credential in the credential store.

The credential store securely holds the credentials that Couchbase services and users use to authenticate with external systems, such as AWS S3, REST APIs, or another Couchbase instance.
For more information, see xref:learn:security/credential-store.adoc[].
 
To create a credential, provide a unique name, the target system type, and the required authentication fields.
You can also add optional details, such as a description, an expiration date, and guardrails that limit how the credential is used.

After you create a credential, you can reference it by name in other statements or features without specifying the raw credentials directly.

[NOTE]
==== 
* The `CREATE CREDENTIALSTORE` statement is available only in Couchbase Server 8.5 and later.
* To grant other users or groups access to a credential that you created, use the `GRANT CONSUME CREDENTIALSTORE` statement. 
For more information, see xref:n1ql:n1ql-language-reference/grant.adoc[].
====

== Prerequisites

Before you run the `CREATE CREDENTIALSTORE` statement: 

* You must enable credential store. 
For more information, see xref:manage:manage-security/manage-credentials/manage-credential-store.adoc[].
* You must have one of the following roles:
+
--
** Full Admin
** Credential Admin
** Security Admin
--
+
For more information about roles and privileges, see {roles}[Roles].

=== WITH Clause

The `WITH` clause accepts a JSON object with the following fields. 

[cols="1,2,1", options="header"]
|====
| Name | Description | Schema

| **type** +
__required__

a| The type of external system the credential authenticates with.

For the list of supported types and their fields, see xref:manage:manage-security/manage-credentials/manage-credential-store.adoc#type-fields[Credential Types and Fields].

NOTE: You cannot change the type after you create the credential.

| String

| **fields** +
__required__

| The authentication parameters corresponding to the specified `type`.
For the required and optional fields for each type, see xref:manage:manage-security/manage-credentials/manage-credential-store.adoc#type-fields[Credential Types and Fields].

| Object

| **description** +
__optional__

| A description of the credential.

| String

| **expiresAt** +
__optional__

| An expiration timestamp in epoch milliseconds. 
The timestamp must be set to at least 5 minutes in the future.
After this time passes, requests that use the credential fail with an error.

| Number

| **guardrails** +
__optional__

| Access control policies that restrict where and how the credential can be used. 
For example, limiting usage to specific services or URLs. 

For more information, see xref:learn:security/credential-store.html#guardrails[Guardrails].

| <<guardrails>> object
|====

=== Guardrails

[cols="1,2,1", options="header"]
|====

| Name | Description | Schema

| **allowedServices** +
__optional__

| A list of Couchbase services (such as `n1ql`, `backup`, `index`) permitted to use the credential. 

If omitted, all services can use the credential. 

| Array of strings

| **urlWhitelist** +
__optional__

| Restricts the target URLs where the credential can be applied. 

| <<whitelist>> object
|====

==== Whitelist

[cols="1,2,1", options="header"]
|====

| Name | Description | Schema

| **allAccess** +
__optional__

| Determines whether the credential can access all URLs.

If set to `true`, the credential can access all URLs, and overrides both `allowedUrls` and `disallowedUrls`.

If set to `false`, `allowedUrls` and `disallowedUrls` control access.

| Boolean

| **allowedUrls** +
__optional__

| URL patterns where the credential can be used.

| Array of strings

| **disallowedUrls** +

| URL patterns where the credential cannot be used.

| Array of strings
|====

NOTE: Couchbase masks secret values (such as `secretAccessKey`, `accountKey`, or `clientSecret`) upon submission and does not return them in plain text.
//end::with-clause[]

== Examples

.Create a credential named `awsid` for an AWS access key
====

[source,sqlpp]
----
CREATE CREDENTIALSTORE `awsid` WITH {
    "type": "aws",
    "fields": {
        "accessKeyId": "AKIAIOSFODNN7EXAMPLE",
        "secretAccessKey": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
        "region": "us-west-2"
    }
};
----
====

.Create a credential with a description, an expiration date, and guardrails
====

[source,sqlpp]
----
CREATE CREDENTIALSTORE `backup_s3` WITH {
    "type": "aws",
    "fields": {
        "accessKeyId": "AKIAIOSFODNN7EXAMPLE",
        "secretAccessKey": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
        "region": "us-west-2"
    },
    "description": "S3 access for backups",
    "expiresAt": 1798761600000,
    "guardrails": {
        "allowedServices": ["backup"],
        "urlWhitelist": {
            "allAccess": false,
            "allowedUrls": ["https://s3.amazonaws.com/*"]
        }
    }
};
----
====
