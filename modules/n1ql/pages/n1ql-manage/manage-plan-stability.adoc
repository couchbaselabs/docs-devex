== Configure Plan Stability

You can configure plan stability using one of the following methods:

* At the cluster level: 
** <<using-the-web-console, Using the Couchbase Server Web Console>>
** <<using-the-update-statement, Using the `UPDATE` statement>>
* At the statement level: 
** <<using-the-prepare-statement, Using the `PREPARE` statement>>

=== Using the Web Console

When you configure Plan Stability in the Couchbase Server Web Console, settings apply automatically to every query node in your cluster. 

. In the Couchbase Server Web Console, go to menu:Settings[Query].
. From the *Plan Stability* list, select a mode. 
+
--
* `Off`: Does not save execution plans to disk.
Prepared statements remain in memory only and are cleared if the query node restart or upgrades.
* `On Prepared Statements`: Saves execution plans to disk for all prepared statements.
* `On All Statements`: Saves execution plans to disk for all queries, including prepared statements and ad-hoc queries.
* `Frozen`: Does not save execution plans to disk for new queries, but uses existing saved plans for matching queries.
--
. From the *Plan Stability Error Policy* list, select an error policy. 
+
--
* `Strict`: Stops execution and returns the error to the application.
* `Moderate`: Generates a new plan to execute the statement, but keeps the original saved plan.
* `Flexible`: Generates a new plan to execute the statement and overwrites the saved plan with the new one.
--
For more information, see xref:n1ql:n1ql-manage/query-plan-stability.adoc#error-policies[Error Policies].

. Click btn:[Save].

=== Using the UPDATE Statement

You can also configure Plan Stability programmatically by running an `UPDATE` statement against the `system:settings` catalog.
These settings apply at the cluster level to every query node in your cluster.

To set the Plan Stability mode:

[source,sqlpp]
----
UPDATE system:settings SET plan_stability.mode = "off";
----

To set the Plan Stability error policy:

[source,sqlpp]
----
UPDATE system:settings SET plan_stability.error_policy = "moderate";
----

To get a list of acceptable values for `plan_stability.mode` and `plan_stability.error_policy`, see xref:n1ql:n1ql-intro/sysinfo.adoc#sys-settings[Monitor Settings].

=== Using the PREPARE Statement

When you use the `PREPARE` statement, you can explicitly specify which plans to persist using `SAVE` keyword. 

* With `SAVE`: Saves the execution plan to disk. 
* Without `SAVE`: Keeps the execution plan in memory only. 

The following example shows the usage of the `SAVE` keyword: 

[source,sqlpp]
----
PREPARE SAVE get_route_by_airline FROM
SELECT * FROM route
WHERE airline = "FL";
----

For more information, see the xref:n1ql:n1ql-language-reference/prepare.adoc[PREPARE] statement.

== View Saved Plans

You can view saved execution plans using the `system:prepareds` keyspace.

For prepared statements, the saved plan appears under the name you specified when you ran `PREPARE`.

For ad-hoc queries (when the Plan Stability mode is `On All Statements`), the Query Service automatically prepares each query using xref:n1ql:n1ql-language-reference/prepare.adoc#auto-prepare[auto-prepare].
Because these statements have no local name, the service generates a name from the statement text.

To view all saved plans, including both prepared and ad-hoc statements:

[source,sqlpp]
----
SELECT *, meta().plan FROM system:prepareds;
----

To find the saved plan for a specific ad-hoc query, filter by the statement text:

[source,sqlpp]
----
SELECT *, meta().plan FROM system:prepareds WHERE statement LIKE "%FROM route WHERE airline%";
----

For more information, see xref:n1ql:n1ql-manage/monitoring-n1ql-query.adoc#sys-prepared[Monitor and Manage Prepared Statements].

== View Plan Stability Settings

You can view the cluster-wide Plan Stability settings using the `system:settings` catalog.

[source,sqlpp]
----
SELECT * FROM system:settings;
----

This returns the current `mode` and `error_policy` values, for example:

[source,json]
----
[
  {
    "settings": {
      "plan_stability": {
        "mode": "ad_hoc",
        "error_policy": "moderate"
      }
    }
  }
]
----

For more information, see xref:n1ql:n1ql-intro/sysinfo.adoc#sys-settings[Monitor Settings].

== Plan Execution & Persistence Flow ==

Client -> QS : Submit Query (Ad Hoc or Prepared)
activate QS

alt Query Execution Verification
    QS -> QS : Verify dependencies\n(Indexes, Keyspaces)
    alt Verification Failed
        QS -> Client : Handle error per configured Error Policy
    end
end

alt Ad Hoc Query
    alt Cluster Setting = OFF or ON PREPARED STATEMENTS
        QS -> QS : Build query plan
        QS -> Client : Execute statement
        QS -> QS : Discard plan
    else Cluster Setting = ON ALL STATEMENTS
        QS -> QS : Auto-prepare query
        QS -> QS : Generate query plan
        QS -> Meta : Save plan to QUERY_METADATA
        QS -> Client : Execute statement
    else Cluster Setting = FROZEN
        alt Matching Saved Plan Exists
            QS -> Meta : Fetch existing saved plan
            Meta --> QS : Return plan
            QS -> Client : Execute statement using saved plan
        else No Matching Saved Plan
            QS -> QS : Build temporary plan
            QS -> Client : Execute statement (Do not save plan)
        end
    end

else Prepared Statement
    alt Cluster Setting = ON PREPARED STATEMENTS / ON ALL STATEMENTS \nOR Executed via PREPARE with SAVE
        QS -> QS : Generate query plan
        QS -> Meta : Save plan to QUERY_METADATA
        QS -> Client : Execute statement
    else Cluster Setting = OFF (Without SAVE)
        QS -> QS : Build query plan
        QS -> Client : Execute statement
        QS -> QS : Discard plan
    end
end

deactivate QS

Client -> SystemCat : Query system:prepareds
activate SystemCat
SystemCat --> Client : Return saved query plans
deactivate SystemCat

[-> QS : Couchbase Server Upgrade / Restart
activate QS
QS -> Meta : Read saved plans
activate Meta
Meta --> QS : Return saved plans
deactivate Meta
QS -> QS : Reload plans directly into memory
deactivate QS
