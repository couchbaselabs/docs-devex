= Query Plan Stability
:page-topic-type: concept
:page-status: Couchbase Server 8.5
:page-edition: Enterprise Edition
:description: Query Plan Stability enables you to save and reuse query plans across upgrades.

[abstract]
{description}

== Overview

Query Plan Stability, or Plan Stability, preserves query execution plans across Couchbase Server upgrades and node restarts. By saving and reusing plans, this feature helps you avoid performance regressions caused by changes to the query optimizer.

By default, the query optimizer generates a new plan for a query whenever no plan is in memory:

* For prepared statements, the optimizer generates a plan once and caches it in memory.
* For ad-hoc queries, the optimizer generates a new plan each time you run the query, unless a matching plan is already in memory.

Cached plans clear after an upgrade, so the optimizer in the new version might generate a different plan for the same query.
This can cause unexpected changes in query performance.

Plan Stability solves this problem by saving execution plans to persistent storage. 
After an upgrade or restart, Couchbase Server reloads and reuses these saved plans.

== Key Benefits

Plan Stability provides the following benefits: 

* Consistent Execution: Queries can run with the same plan across upgrades.
* Performance Stability: Reduces the risk of performance degradation from optimizer changes. 
* Application Protection: Protects applications tuned for specific query plans.

== Enable Plan Stability

You can enable Plan Stability at the cluster level using the Couchbase Server Web Console. 

The cluster-level setting has three options:

* *Off*: Plan Stability is turned off. The Query Service does not save any plans. 

* *On Prepared Statements*: The Query Service saves only plans for prepared statements and generates a new plan for each ad-hoc query.

* *On All Statements*: The Query Service saves all plans, including prepared statements and ad-hoc queries.
It generates a new plan only if no saved plan exists.

You can also enable Plan Stability for individual queries. 
When you prepare a statement using `PREPARE`, you can save the plan using the `SAVE` keyword.

For more information about enabling and managing Plan Stability, see xref:n1ql:n1ql-manage/configure-plan-stability.adoc[].

== Storage 

Couchbase Server stores saved execution plans in a dedicated, user-level bucket called `QUERY_METADATA`.
It automatically creates this bucket when you do one of the following:

* Issue a `PREPARE` statement with the `SAVE` keyword.
* Set the Plan Stability mode to *On Prepared Statements* or *On All Statements*.

The `QUERY_METADATA` bucket uses a default memory quota of 100 MB.

[NOTE]
====
* Users with admin privileges can drop the `QUERY_METADATA` bucket.
* Dropping the bucket manually can trigger runtime errors during query execution.
* Setting the Plan Stability mode to *Off* does not automatically drop this bucket.
* If you drop the bucket, Couchbase Server automatically recreates it the next time you issue a `PREPARE` statement with `SAVE`, or set the Plan Stability mode to a setting other than *Off*.
====

== Error Policies

Before running a saved query plan, the Query Service verifies whether the plan is still valid.
A saved plan can become invalid over time. 
For example, if an index used in the plan is dropped, the plan becomes invalid and cannot be used. 
When plan verification fails, the Plan Stability error policy determines how the service responds.

Plan Stability supports the following error policies:

[cols ="1,3", options="header"]
|===
| Error Policy | Description

| Strict 
| Stops statement execution and returns an error to the application. 

| Moderate
| Reprepares the statement to generate and run a new plan. 
The original saved plan remains unchanged. 

This policy is useful when an index becomes temporarily unavailable. 
Statement executions might use a suboptimal plan while the index is down, but the saved plan stays intact, and you can reuse it once the index becomes available. 

| Flexible
| Reprepares the statement to generate a new plan and replaces the saved plan with the new one.  

This behavior is similar to the standard prepared statement handling.
|===

For instructions on how to set the error policy, see xref:n1ql:n1ql-manage/configure-plan-stability.adoc[].
