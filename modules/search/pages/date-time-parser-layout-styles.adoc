= Date/Time Parser Layout Styles
:page-topic-type: reference
:page-ui-name: {ui-name}
:page-product-name: {product-name}
:description: When you create a custom date/time parser with the Couchbase {page-ui-name}, you must choose a specific layout style for your date/time layouts.

[abstract]
{description}

You can choose from the following layout styles for a date/time parser. 

TIP: Date/time layouts should always be surrounded by quotes.

[cols="1,2,2"]
|====
| Layout Style | Description | Example Layouts

| *flexiblego*
a| Date/time layouts must be provided with golang specific constants. 

A *flexiblego* date/time layout is not validated automatically by the {page-ui-name}.

For more information about *flexiblego* time layout syntax, see <<go,>>.
a| `"01/02 03:04:05PM '25 -0700"`

`"Mon Jan _2 15:04:05 MST 2025"`

`"Monday January 02 15:04:05 -0700 2025"`

`"2025-01-02T15:04:05Z07:00"`

| *isostyle*
a| Date/time layouts must be provided as ISO date format strings, commonly used in programming languages like Java and Swift. 

Letters in the range A-Z and a-z are reserved for layout patterns.
Any other characters are considered as a literal part of a date string.

The count of pattern letters determines the specific format.

For more information about *isostyle* time layout syntax, see <<iso,>>.
a| `"yyyy/MM/dd h:mma"`

`"dd/MM/yyyy HH:mm:ss"`

`"yyyy-MM-dd'T'HH:mm:ssXX"`

`"dd MMMM yy ha z"`
        
`"yyyy; MMM dd (EEE) hh:mm:ss.SSSSSaa xx"`


| *percentstyle*
a| Date/time layouts are provided using format specifiers surrounded by `%` characters, commonly used in programming languages like C and Python.

Any other characters in a layout string are considered literal characters.

For more information about *percentstyle* time layout syntax, see <<percent,>>.
a| `"%Y/%m/%d %l:%M%p"`

`"%d/%m/%Y %H:%M:%S"`

`"%Y-%m-%dT%H:%M:%S%z"`

`"%d %B %y %l%p %Z"`

`"%Y; %b %d (%a) %I:%M:%S.%N%P %z"`


| *sanitizedgo*
a Date/time layouts are provided with the same constants and format as *flexiblego*, but with strict RegEx-based validation. 

*sanitizedgo* layouts must match the standard layouts from RFC standards, such as RFC3339, RFC822, and RFC1123.

For more information about *sanitizedgo* time layout syntax, see <<go,>>.
a| `"01/02 03:04:05PM '25 -0700"`

`"Mon Jan _2 15:04:05 MST 2025"`

`"Monday January 02 15:04:05 -0700 2025"`

`"2025-01-02T15:04:05Z07:00"`

|====

*isostyle* date/time layouts use the following syntax:

|====
